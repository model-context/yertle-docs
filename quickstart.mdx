This guide walks you through authenticating, listing your organizations, and reading a node from the Yertle API.

## 1. Get an account

Sign up at [yertle.com](https://yertle.com) and create or join an organization.

## 2. Generate a Personal Access Token

Sign in to [yertle.com](https://yertle.com), open your [settings page](https://yertle.com/settings), and under **Personal Access Tokens** click **Create token**. Give it a descriptive name (e.g. "quickstart laptop") and copy the token — it starts with `yrt_` and you'll only see it once.

Export it:

```bash
export YERTLE_TOKEN="yrt_..."
```

To have the Yertle CLI store the token for you instead, see the [Authentication guide](/authentication).

## 3. Make your first API call

List the organizations you belong to:

```bash
curl https://api.yertle.com/orgs \
  -H "Authorization: Bearer $YERTLE_TOKEN"
```

You should see a JSON response with your orgs:

```json
{
  "organizations": [
    {
      "id": "ed411977-...",
      "name": "Acme Inc.",
      "role": "owner"
    }
  ]
}
```

## 4. Read a node

Pick an org ID and a node ID from your workspace, then fetch the node's tree document:

```bash
curl https://api.yertle.com/orgs/{org_id}/nodes/{node_id}/tree/main \
  -H "Authorization: Bearer $YERTLE_TOKEN"
```

You get the node exactly as it is stored, plus read-only context (trimmed here to one of two children):

```json
{
  "expected_head_commit": "922ee368-...",
  "message": "",
  "state": {
    "node": { "title": "Node AAA", "description": "Parent node that will contain BBB and CCC", "metadata": {} },
    "tags": { "environment": { "value": "test" } },
    "directories": ["/test"],
    "visual_properties": [
      {
        "child_node_id": "7508d70f-...",
        "position_x": 100.0,
        "position_y": 100.0,
        "z_index": 1,
        "width": 200.0,
        "height": 100.0,
        "rotation": 0.0,
        "transparency": 1.0,
        "show_border": true,
        "title_position": "top-left",
        "show_preview": false,
        "_title": "Node BBB",
        "_description": "Child node with egress connection to CCC",
        "_snapshot_commit_id": "ccfcaba9-..."
      }
    ],
    "connections": [
      {
        "id": "3f7aba27-...",
        "from_child_id": "7508d70f-...",
        "to_child_id": "ab687693-...",
        "from_edge": "right",
        "to_edge": "left",
        "style": {},
        "label": "connects to",
        "type": "default",
        "metadata": {},
        "_from_title": "Node BBB",
        "_to_title": "Node CCC"
      }
    ]
  },
  "status": {
    "node_id": "ee39e1f1-...",
    "org_id": "8048e799-...",
    "branch": "main",
    "parents": [],
    "ingress": [],
    "egress": [],
    "counts": { "children": 2, "connections": 1, "parents": 0, "ingress": 0, "egress": 0 }
  }
}
```

- **`state`** is what [push](/api-reference/nodes/push-node-state) takes. To change the node, edit `state` and send it back with `expected_head_commit`; if someone pushed in between, you get `409` instead of overwriting their work.
- **Fields starting with `_`** (a child's `_title`, its `_snapshot_commit_id`) and everything in **`status`** are read-only context. Push ignores them, so you can send the document back without stripping them.
- **At a commit**, `GET .../tree/{branch}/commits/{commit_id}/tree` returns the same shape without `expected_head_commit`: a historical read, not something to push.

## Prefer Python?

Install the SDK into your project — same three-line quickstart in code:

```bash
uv add yertle
```

`uv add` works inside a uv project; run `uv init` first if you don't have one.

```python
import yertle

yertle.configure(token="yrt_...")
for org in yertle.orgs.list():
    print(org.name)
```
